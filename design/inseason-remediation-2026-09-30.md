# 季賽助手的計算與資料契約補充

日期：2026-09-30。這份文件記錄本機修復候選採用的契約及假設，不是整份規格的驗收報告。原規格、交接清單與使用者後續指示仍是需求依據。候選尚未提交或推送，不能據此宣稱里程碑完成。

## 資料與來源界線

使用者只接受免費、且條款允許本用途的來源；原缺陷腳本、排陣案例、接受模型資料及歷史回測資產沒有另行提供。本機新增案例是自行建立的合成資料，不能代替真實 Yahoo 授權、供應商回應或歷史樣本外驗證。

尚未取得涵蓋逐場數據、傷病、賽程及此用途權利的完整免費來源。自訂 JSON 入口仍不是現成 NBA adapter，F1–F6 的真實資料初始化缺口仍存在。不註冊付費服務、不把禁止建立資料庫的網站改成爬蟲入口，也不捏造缺少的排名、持有率或比分。

Yahoo 的比分 `through` 表示取回時間，不能證明已完成比賽入帳。新增可選的 `complete_through` 表示經證實的涵蓋時間；Yahoo adapter 目前不會自行填入。已完賽但無涵蓋證據、或已開賽且無法辨認部分比分時，計算明確不可用。這項防錯契約尚不能替代真實來源語義驗收。

球員比對優先使用 provider ID／Yahoo editorial ID，其次才用唯一的姓名、球隊及位置組合；歧義保留待確認。持有率未知與 0 分開，附來源時間。

## 預測、抽樣與排陣

本週模擬使用 `simulations`，剩餘賽季使用 `season_simulations`；預設分別為 1,000 與 200。亂數流按固定 seed、球員、比賽及抽樣元件分開，較少樣本使用相同流的前綴；不同抽樣數的陣列不混用。

個人沒有逐場歷史時，`prior_predictive=nested_poisson` 使用凍結的季前先驗：父計數採 Poisson，受限子計數採條件 Binomial，保留投籃、三分及命中數等物理限制。不以全零或確定常數代替未知。其他統計相關性、尾端機率及新秀預測品質尚無 holdout 證據。

每日合法候選完整列舉；批次化不刪除候選。整週合法組合數小於等於 `weekly_exact_candidates` 時才做聯合窮舉；超過則逐日精確解、反覆改善，畫面明示不保證整週全域最佳。不得把小案例的聯合最優證據外推為真實規模的品質保證。

IL 回歸情境依日期、資格及容量決定 activation 和必要 drop，只提供建議。必要釋出比較包含所有設定中的剩餘週與季後賽，未知對手明確不可計算，不能因只剩季後賽就把所有候選估值當成零。未知回歸日期不猜。多名球員回歸採時間順序處理，尚未證明聯合最優；IL 回歸與未來 add/drop transitions 的組合目前明確拒絕，不宣稱此組合已支援。

## 本週目標、換人與今日頁

依使用者後續決定，必勝只限輸球即淘汰，或輸這週必定無緣季後賽、贏球仍有晉級路徑。排名壓力不算；已經出局且贏也沒有路徑時，不犧牲整季強度。

例行賽需先確認 `playoff_seeding=overall`、各隊已入帳場數相同及完整剩餘對戰。用離散勝／敗／和結果可行性判定，不把 Monte Carlo 的 0% 當成確定出局。即使最終同分全部有利仍無法晉級，才證明輸球出局；贏球需有不依賴同分的晉級路徑。Yahoo 的例行賽同分規則不是目前 seed：[Yahoo 規則](https://help.yahoo.com/kb/head-to-head-scoring-yahoo-fantasy-sln6212.html)。本判定採同分上下界，未實作完整歷史同分或分區晉級規則。資料、精度或求解時間不足回傳 `unknown`。季後賽則需明確的 `elimination=true`，不能由 playoff 日期猜成淘汰賽；目前 Yahoo adapter 尚未自動提供這個證據。

一般 F3 計畫除正增益外，`delta_strength` 須大於等於負容差。這個量是配置中所有剩餘週（含季後賽）相同模型的分數差；它不是實證的球員市價。未知未來對手會讓這個檢查不可用，不能假定損失為零。已確認必勝時只比較本週增益，長期損益標 `null` 而不是冒充零。加人額度、名單容量、鎖定與保護球員仍須遵守。

F3 先沿用已算好的 baseline 先發與抽樣，計算凍結先發中的個人隊伍貢獻；只讓貢獻較低的 `drop_shortlist` 人進入完整換人情境。這是候選篩選近似，沒有全域最優或真實召回率保證。驗收 oracle 仍保留全部合法 drop，避免只在同一縮小候選集合內自我驗證。

合法的中間換人計畫仍可延伸；單步沒有增益或暫時不符整季保護，不代表加入下一步後仍不合格。產品的有限 beam 依分數保留前綴，但只發布符合保護規則的完整計畫；已確認必勝時快速評分考慮所有類別，不因 baseline 標為暫不投入就排除兩步才翻盤的機會。驗收 oracle 會延伸所有合法前綴，只以保護規則過濾評分結果，不共用產品的 beam 或前綴剪枝，也不把受搜尋上限中斷的結果認證為最佳。

今日頁不再逐一移除名單球員、重跑整季 drop／replacement 搜尋。它顯示實際對手、需守住／爭取／暫不投入的類別，並沿用同資料、帳本、參數及換人偏好的已保存 F3 計畫；任一未執行 move 已過合法生效或球員鎖定時間，整份計畫需重新計算，不能因資料雜湊沒變就視為已取得球員。沿用計畫後的今日排陣以完成該計畫為前提，釋出球員不再同時被建議先發。沒有保存計畫時明示前往本週頁。

IL 也沿用已計算的回歸／必要 drop 計畫。建立我方計畫時排除保護球員，保護設定變更會使舊 simulation 快取失效；今日頁也重查既有 IL 決策，不能建議釋出目前受保護的人。完整週計算若所有合法對象均受保護，明確回報 IL 待處理，需調整設定或手動騰出名額後同步。有空位時可直接建立無 drop 的回歸情境；冷啟動時名單已滿且沒有有效計畫，今日頁明示待確認，暫不把該啟用算進排陣與預測，也不偷偷重跑整季搜尋。此為使用者要求沿用既有建議後的明確待辦邊界，不能說成完整 IL 全域最佳。

已採用預估回歸情境且到達生效日時，今日頁同時列出移出傷兵格與必要釋出的動作，即使來源狀態仍是 `INJ`。文字明示依預估情境、仍須確認實際回歸；動作與條件排陣一致，不能因仍有傷病標籤而漏掉啟用，也不能冒稱已健康。

跨日會重建 simulation，不把昨日的健康假設帶入今日。預估回歸日已到、最新傷病資訊仍來自該日期之前時，今日頁保留 IL 待確認提示；即使名單有空位，也不直接啟用或搜尋必要丟人。來源在回歸日或之後更新且仍確認受傷時，以該狀態為準，取消舊估計；來源確認健康後再依正常 IL 資格與容量處理。

## 自動交易的價值範圍與精算

依使用者後續指示，自動搜尋先套公開價值門檻。每位球員沿用同一個 `rank_value` 公式與當時有效的公開排名；整包加總後，以 `min(V_home,V_away)/max(V_home,V_away)` 比較。使用者偏好 `trade_value_min_ratio` 預設為 0.70，可在 0.50–1.00 間調整：100% 最嚴格、只接受相等估值，50% 最寬鬆、允許兩倍差距。70% 是建議初值，沒有實證接受率或市場公平性的校準證據。畫面說明估值 100 對至少 70，不能把門檻誤讀成接受機率。

偏好 schema 是上下限與預設值的唯一來源，bootstrap 將其交給畫面。拖動後下一次搜尋先保存新偏好；也可單獨保存，重載後保留。範圍外或無效值在寫入前拒絕，舊偏好檔缺該欄位時讀取為 0.70。搜尋結果保存實際使用的門檻及原組合、缺排名、價值差排除、進入比較、完整情境與上界略過的計數。缺公開排名的自動組合明示略過；手動組交易不受此門檻限制，缺排名時仍給隊伍影響，接受率與期望值保持未知。

目前通過價值門檻的 1 換 1 仍完整評估。多換多仍比較每邊一至所選人數的合法組合，以增益上界較高者先算，只有數學上界不能進入前十名時才略過；不因較小交易沒有增益就刪掉其更大組合。人數不等時仍以同一 ROS 模型比較必要補人／釋出，只有分數上界能證明結果不變時才省略完整計算，保留原來的 ID 平手順序；我方自動釋出排除保護球員。使用者已明確選擇保留完整搜尋、繼續改善精確演算法，不採交易 shortlist、beam 或較少抽樣。完整交易的 30 秒效能仍需個別證據，不把逾時的部分結果發布成完整推薦。

交易需要補人時，共同名單與實際每週對手的抽樣只建立一次。先完整計算 ID 最前的合法自由球員，再以同一批剩餘比賽抽樣、放寬先發格與資格限制算出其他人的 ROS 分數上限；只有上限仍可能勝過目前最佳人選（包含容差與 ID 平手順序）才完整求排陣。所有合法自由球員仍經過上限比較，不以排名取前幾人。自身有未來名單轉換、需投影 IL 回歸、可能報分母錯誤，或無法取得有限上限時，保留原完整比較；補人仍逐步選擇，未改成聯合最優。實際時間與完整結果一致性記於 Git 外報告。

交易沿用競標桌的 `worker_limit`／`parallelism`：預估剩餘天數、ROS 抽樣及名單補／丟比較量，工作少時單核心，工作多時最多用可用邏輯核心的四分之三。每四百萬 sample/team/days 的啟用粒度沿用競標桌的政策假設，不是已校準的最佳門檻。Jobs 擁有延遲建立的 spawn pool；退出時取消並等待工作清理。worker 意外退出明確失敗，下次才重建，不回傳部分成功結果。

我方、候選對手與聯盟原始名單的共同基準先算一次，再複製私有快取給各 worker；不同 worker 不共享可變快取，也不傳送大量逐場抽樣陣列。1 換 1 切成每核心兩批的連續候選，讓閒置核心接剩餘工作；多換多仍分配全部通過門檻的候選，各批使用保守上界，合併後按同一規則排序。取消的 IPC 檢查以 50ms 間隔合併，deadline 仍在原計算檢查點檢查，主程序也在發布前確認取消與時限。失敗時的完成計數僅涵蓋已回傳的整批，不能解讀成所有 worker 的已嘗試數。

搜尋清單只保存完整計算後的交易摘要，避免每筆都複製整季排陣與類別詳情。摘要仍含雙方增益、排名、接受率、期望值、季後賽與自動補／丟結果。點選期望值後，既有手動評估入口以目前資料產生完整公式與每週類別；手動指定交易保持完整回應。只算純量的中間結果不能冒充完整詳情。剩餘賽季純量仍由同一批抽樣、排陣、校準與加總產生，不減少週數、對手或補人候選。

人數差超過一時，補／丟人仍是逐步選擇，尚無聯合最優證明。1 換 3 的第一次內部釋出比較允許暫時超過容量，已知且不重複的球員仍須確認，最終名單才發布並通過正常容量檢查；不能因第一步尚多一人就把可完成的交易判為不合法。

每日排陣以當日可選抽樣的統計區間計算保守分數上界；只有最多球員、ID 順序優先的合法排陣已達該上界時，才略過其他候選。否則沿用完整列舉，不改抽樣數或合法候選。帶 `zero_denominator=error` 的比率類停用這個捷徑，以保留原本的錯誤行為。共同對手的未改變週積分快取重用；季後賽排名仍遵守原來分數容差、seed 與 ID 平手順序，改用批次排序。補／丟人重複的季分數在既有 `scenario_cache_entries` 界線內保存純量，淘汰後重新計算；沒有持久化到原始資料。

上界在優先合法排陣算完後才求；已達全體抽樣最高可能分數時不需再求較細區間。合法候選的共同前綴可重用統計加總，但維持每筆原來的浮點加法順序，不用重排加總來換速度。有效球員索引依固定 projection 的球員 tuple 身分重用，保留該 tuple 防止身分重用；更換 projection 後取得新的索引。

初始預期數據排陣只對完全相同的先發格／資格、可選球員 ID／位置／均值位元，以及固定球員均值順序重用。結果保存為不可變的 slot／player tuple，取回時建立新的 dict；容量沿用 `scenario_cache_entries`，各 Simulation 及 worker 的快取 map 私有。整週抽樣排陣仍完整計算，今日 roster 的 bench 也重新建立。ROS 分數快取則包含每週實際對手與相關隊伍名單；缺少剩餘對手時先拒絕計算，既有快取也不能掩蓋缺資料。

排陣名單順序在計算入口一致化，避免相同球員集合因 caller 的 tuple 順序或快取淘汰而產生不同板凳排序。這是輸出重播一致性的修復，沒有改變板凳集合、先發或模型分數。

只需要分數或排名積分的剩餘週計算，共用包含雙方實際名單的有界積分抽樣快取。H2H One Win 只有在放寬排陣後仍證明所有樣本連平手都不可能時，才直接保存我方 0、對手 1；這不是用低勝率猜必敗。校準為零或小到非零抽樣機率會與零四捨五入成相同值時，保留完整計算。週詳情仍由原排陣引擎產生，不能把積分證明冒充類別及先發詳情。

多換多的我方分數上界涵蓋平換平，以及需要丟一人的每個未受保護釋出情境；允許不合法的中間名單只會放寬上界。交易對手若也是剩餘週對手，使用其交易後名單；若尚需自動補／丟而無法確定該名單，保留完整比較。未來 transitions、IL 回歸與會產生錯誤的比率仍保留原路徑。只有上界證明進不了前十名，才省略整組精算；完整候選集合與前十名排序維持原契約，較後面的回傳筆數可以減少。

自由球員上界沿用 `lineup_batch` 分批處理，每個候選保持原日期加總順序及向外捨入。單一係數為 ±1 的項目只取對應區間或精確反號，避免多餘的乘法與捨入；其他公式保留一般區間運算。不減少候選、剩餘週或抽樣數。

## 公式層與畫面

出賽場數的線性回歸實作移至公式層，以 `availability_regression` 登錄手算範例與代入值；建置流程只組合並保存校準結果，`core` 不反向依賴公式。保留原十進位有理數計算與整數觀測精度。手調倍率、分鐘重分配、先驗權重與低出賽場數尾段使用既有登錄公式，不另寫相同算式。這些修正不代表全部競標桌及季賽公式已完成盤點與登錄。

收合的算式明確隱藏非標題內容，數字儲存格可換行，避免巢狀表格撐高球員卡。球隊及雙欄版面的欄寬允許縮小至容器內，寬表格在自身捲動區域顯示；沒有改動模型數值或畫面算式來源。

## 快取與保存

Simulation 在固定 league、snapshot、players、priors、parameters、ledger、as-of 資料情境內使用。跨請求重用依完整資料雜湊及日期／資訊變化區間失效；`played_at < as_of` 的嚴格邊界與 history 篩選一致。參數或資料更新建立新的情境。

有效預測只在 active adjustments、有效傷病狀態與適用背靠背手調相同時共用，日期 metadata 仍使用所求日期。scenario LRU 不持久化到原始資料，淘汰不改變模型。

NBA 場次由同一份已通過 as-of 篩選的賽程，依球隊與聯盟日期索引，保留原順序；索引最多保留每場主／客隊各一個參照，賽程或時區變更即重建，沒有跨資料來源的永久快取。換人分支重用既有 ROS 抽樣池，但不混用週抽樣與 ROS 抽樣，也不共用有不同 transitions 的排陣／預測快取。當整個快照沒有 IL 球員且所有 move 已在剩餘週之前生效，未來計算可用最終名單重用原 ROS 引擎的名單快取；有 IL 或較晚生效的 move 保留完整時間軸。

原始 snapshot、帳本、預測及更正歷史不刪除。history 提供有界 payload 查詢；邏輯 ID 索引保留最早紀錄，舊索引首次查詢會一次性遷移。索引本身仍會成長，長季 I/O 與保存策略驗收尚未完成。

預測在同步成功後嘗試保存，不靠開頁補造事前結果。計算失敗與資料同步失敗分開呈現；無 contemporaneous prediction 的舊週不事後補寫。類別與整週匯出、擬合分開，訓練結果一律明記未做 holdout。
